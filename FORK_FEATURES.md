# Доработки форка Multica

Здесь перечислены доработки ветки `Mexanik72/multica:fork/main` относительно `upstream/main`. Обновляйте этот список при добавлении, изменении или удалении доработки. Порядок синхронизации описан в [FORK_WORKFLOW.md](FORK_WORKFLOW.md).

## База upstream

Форк синхронизирован с официальным тегом [`v0.13.0`](https://github.com/multica-ai/multica/releases/tag/v0.13.0), коммит [`35b54a374`](https://github.com/multica-ai/multica/commit/35b54a3742bb51bdf5ffa688655367ec98044862). Предыдущая база — `fc8028d76` (`0.12.1`); [120 новых коммитов upstream](https://github.com/multica-ai/multica/compare/fc8028d761707b506cec498385f31fcebbbff598...35b54a3742bb51bdf5ffa688655367ec98044862). Изменения `main`, вышедшие после этого тега, в эту синхронизацию не входят.

В эту синхронизацию вошли:

- [Дополнительные инструкции работающему Hermes](server/pkg/agent/hermes_supplement.go) через ACP `/steer` в задачах и Chat. Требуется Hermes версии не ниже `0.22.3` с поддержкой этой команды.
- [Apps hub](packages/views/apps/components/apps-page.tsx): двухколоночная страница с независимой прокруткой, постепенной загрузкой и кэшированием каталога. [Месячная квота вызовов Composio](server/internal/service/app_tool_call_quota.go) учитывает тариф и число мест только при подключённом Multica Cloud; удалённые MCP-вызовы в неё не входят. Apps по-прежнему требует отдельной настройки и по умолчанию не включён в self-hosted стек; Mobbin остаётся встроенным удалённым MCP-приложением с OAuth.
- [Редактор навыков](packages/views/skills/components/skill-detail-page.tsx) сохраняет текст, введённый во время предыдущего сохранения. Источники импорта навыков не изменились.
- [Блокирующие связи задач](server/internal/service/issue_blocker.go), фильтр Blocked и автоматический запуск назначенного агента после завершения всех блокирующих задач.
- [Прямые передачи внутри squads](server/internal/service/squad_handoff.go), аналитика по squads и возможность отключить уведомления о внутренних передачах.
- [Перенос времени wakeup в чате](apps/docs/content/docs/chat.mdx), изменение видимости runtime из списка и быстрый выбор частых агентов через Alt/Option+1–3.

Эти возможности не заменяют перечисленные ниже доработки форка. Система Plugins V1, явный вызов выбранных навыков, wakeups в чатах и сервис совместного редактирования `collab` уже входили в предыдущую базу. Новый каталог плагинов или Harness Hub в `0.13.0` не появился. Совместное редактирование документов и описаний задач в self-hosted установке по-прежнему включается отдельно через сервис `collab` и feature flags.

## Доработки в `fork/main`

| Доработка | Что добавлено | Документация и код |
| --- | --- | --- |
| Интеграция Mattermost | Бот принимает личные сообщения и упоминания в каналах, отвечает в тредах и создаёт задачи по команде `/issue`. Команды `/new`, `/clear` и `/help` управляют разговором и показывают справку. В self-hosted установках Mattermost доступен вместе с WeChat. | [Настройка и команды](apps/docs/content/docs/mattermost-bot-integration.mdx) |
| Вложения и подтверждение приёма в Mattermost | В задачу или разговор передаются вложения сообщения и корня треда. Принятое к обработке сообщение получает реакцию `eyes`. | [Входящие сообщения](server/internal/integrations/mattermost/inbound.go), [вложения](server/internal/integrations/mattermost/media.go) |
| Уведомления об упоминаниях в Mattermost | Общий бот отправляет личное сообщение при прямом упоминании пользователя в задаче или комментарии. Получатель определяется по имени пользователя Mattermost. | [Уведомления](server/internal/integrations/mattermost/mention_notifications.go) |
| Доступ Hermes к инструментам MCP | Для агента Hermes на назначенном runtime можно разрешать отдельные инструменты MCP рабочего пространства и переключать группы чтения и записи. Upstream позволяет включать и выключать сервер целиком; ограничения на отдельные инструменты остаются доработкой форка. | [Настройка доступа](packages/views/agents/components/tabs/mcp-tool-access-dialog.tsx), [применение политики](server/internal/daemon/execenv/hermes_home.go) |
| Сохранение и просмотр навыков Hermes | Навыки, созданные во время задач, сохраняются на daemon отдельно для агента и профиля и переживают последующие запуски. Навыки агента и профиля доступны в списке при онлайн-runtime; владелец runtime может просматривать содержимое. Отслеживание путей выбранных навыков и новый `/steer` из upstream работают вместе с этим хранилищем. | [Хранение навыков](server/internal/daemon/execenv/hermes_skills.go), [просмотр](server/internal/daemon/local_skills_hermes.go) |
| Docker-образы форка | CI проверяет self-hosted сборку и публикует образы backend, веб-клиента и дополнительного сервиса `collab` в GHCR с общим тегом коммита. | [Развёртывание](FORK_WORKFLOW.md#ci-для-docker), [workflow](.github/workflows/fork-docker.yml) |
| Руководство по достижению цели с wakeups | Пример настройки задачи, в которой агент продолжает работу по напоминаниям до достижения цели. | [Руководство](apps/docs/content/docs/reach-a-goal-with-wakeups.mdx) |

## В разработке

| Доработка | Статус и назначение |
| --- | --- |
| Импорт навыков из Harness Hub | Полная реализация остаётся в локальных незакоммиченных изменениях `agent/mcp-tool-access` и не входит в эту синхронизацию `fork/main`. Она добавляет self-hosted источник для импорта отдельных навыков и пакетов по URL с последующим обновлением. Импортирует навыки Multica, а не runtime-плагины, hooks или другие части плагина. |
